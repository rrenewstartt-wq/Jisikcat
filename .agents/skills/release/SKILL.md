# 출고

먼저 해당 회차의 status를 확인하고 작업 지시를 연다.

```sh
python3 tools/studio.py brief EPISODE release
```

1. 검수 승인 버전과 실제 파일의 해시를 비교한다.
2. 최종 영상, 썸네일, 자막, 설명문, 라이선스 기록을 함께 묶는다.
3. 승인받은 채널·공개 범위·예약 시간을 기록하고 게시한 경우 실제 URL을 확인한다.

작업 결과와 남은 의문을 회차 산출물에 적고 CLI의 submit으로 인계한다.

출고 직전에 status와 metrics에서 이번 버전의 대조 심사·독립 검수가 유효한지 확인한다. 직전 승인 이후 바뀐 파일은 새 원본으로 재검수한다.

## 담당자의 결정과 인수 검사

제작 진행 책임자가 병목과 인수 버전을 추적하고 승인된 납품 패키지를 확정한다.

- **인계 기록.** 회차 착수 때 status에서 병렬 가능한 팀과 담당자를 정하고 막힌 작업에 파일·선행 팀·재개 조건을 적는다. 출고에서는 delivery.md에 영상·썸네일·자막·메타데이터 버전, 공개 범위·예정 시각을 적는다.
- **실제 검사.** 해시·파일 재생·마지막 자막·설명 크레디트를 확인한다. 준비·예약·공개 상태를 따로 기록하고 실제 게시했다면 대상 게시물과 표시 상태를 다시 읽어 확인한다.
- **수정 경로.** 버전이 달라졌으면 QA와 해당 제작팀에 돌리고 같은 패키지를 새로 구성한다. 일정 지연은 담당자·미결 산출물·재개 조건을 함께 알린다.
