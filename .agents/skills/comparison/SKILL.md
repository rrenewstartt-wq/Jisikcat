# 레퍼런스 대조팀

`python3 tools/studio.py brief EPISODE comparison`을 연다. 승인된 evidence, edit, marketing 제출과 해당 썸네일을 준비한다. 같은 기능의 장면끼리 비교한다. 러닝타임이 다르면 양쪽 시각도 다를 수 있다.

1. 오프닝·전개·사실·화면·자막·오디오·패키징을 [공통 검수 지침](../../../docs/QUALITY.md)의 방법으로 확인한다. 각 판단에 양쪽 재생 시각, 직접 본 내용, 측정치 또는 출처를 남긴다.
2. 발견한 결함은 증상·기대 결과·담당 팀·재검수 구간과 함께 반송한다. 미확인 항목이 있으면 통과 처리를 보류한다.
3. 수정본 인계 후 변경된 항목과 영향을 받는 다른 구간을 재검사한다. 7개 항목 모두 통과한 시점에 `scorecard.json`과 채운 `handoff.json`을 제출한다.
4. 독립 검수팀이 같은 파일에서 재현할 수 있도록 사실 출처, 프레임 크기, 측정 범위, 예외 근거를 남긴다. 마지막 게시 여부는 출고팀 기록에서 확인한다.

## 담당자의 결정과 인수 검사

기능이 같은 두 장면을 정확한 버전에서 다시 열어 대조 결과를 재현한다.

- **인계 기록.** scorecard.json의 reviewed_inputs를 현재 brief의 세 제출 번호와 맞춘다. 7개 차원에서 reference_at·candidate_at에 양쪽 시각을 따로 적고 finding에 관찰·측정 범위·예외를 쓴다.
- **실제 검사.** 동일 위치의 단순 대입을 피하고 오프닝·첫 증거·결말에서 각각 약속과 수행을 확인한다. 계측 결과가 허용 범위여도 증거나 화면 표현이 오해를 부르면 수정을 요청한다.
- **수정 경로.** 음성은 음향, 자막/화면은 편집, 주장은 대본, 포장은 썸네일·마케팅에 반송한다. 재인계 후 변경된 모든 입력 번호로 문제 구간과 인접 샷을 다시 연다.
