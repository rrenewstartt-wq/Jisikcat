# 독립 검수

먼저 해당 회차의 status를 확인하고 작업 지시를 연다.

```sh
python3 tools/studio.py brief EPISODE qa
```

1. 최종 렌더를 처음부터 끝까지 재생하며 타임코드별 결함표를 만든다.
2. 출처, 사용 조건, 썸네일 약속, 오디오 피크, 자막 잘림, 챕터 시간을 원본과 대조한다.
3. 차단 결함은 책임 팀으로 반송하고 수정본 버전에서 재검수한다.

작업 결과와 남은 의문을 회차 산출물에 적고 CLI의 submit으로 인계한다.

comparison/scorecard.json의 일곱 판정을 읽고 실제 레퍼런스와 납품본에서 인용된 장면을 재생한다. 지목한 불일치가 남아 있으면 해당 팀에 반송한다. 게시 버전의 계측표는 studio.py metrics로 확인한다. 심사 결과를 쓴 사람과 최종 검수자는 서로 다른 담당자여야 한다.

## 담당자의 결정과 인수 검사

독립 검수자가 제작진의 가장 취약한 전제부터 검증하고 최종 판단의 근거를 남긴다.

- **인계 기록.** review.md에 검토 대상 파일·버전, 양쪽 시각, 원자료 위치, 결함과 수정 후 판정을 남긴다. 특히 사실상 보장을 암시하는 제목·수치의 분모·자료 권리와 승인 시점을 원문에서 대조한다.
- **실제 검사.** 비교 심사자와 다른 담당자가 가장 중요한 주장 하나를 재계산한다. 최종 파일을 전편 재생하며 컷 전환·음량 변화·끝부분을 확인한 뒤 크레디트가 실제 자산과 맞는지 본다.
- **수정 경로.** 결함을 최초 발생 팀에 되돌리고 변한 산출물의 자손 단계가 정상 재심사됐는지 status로 점검한다. 열린 결함을 출고 담당자에게 그대로 전달한다.
