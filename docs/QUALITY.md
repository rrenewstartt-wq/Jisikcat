# 기준 영상 대조와 출고 검수

한 회차는 분석 → 기준물 확보 → 기획으로 시작한다. 기획 뒤에는 대본·자료·음향·편집과 썸네일·마케팅을 각 의존 순서에 따라 진행한다. 기준물과 편집본 및 마케팅 패키지가 준비되면 **레퍼런스 대조 → 독립 검수 → 출고 → 성과 분석**으로 이어진다. CLI에서 `teams`와 `brief EPISODE TEAM`으로 실제 파일명과 선행 팀을 확인한다.

## 기준물 확정

`evidence/`에는 같은 영상의 `reference.mp4`, `reference.srt`, `reference.jpg`, `reference.json`을 보관한다. 실물을 갖추고 직접 관찰한 기록과 공개 목록에서 발견한 단서를 구분한다. 예고편, 별도 쇼츠, 번역본으로 표본을 바꾸면 선정 근거부터 다시 검토한다.

| JSON 필드 | 적는 내용 |
|---|---|
| channel_id | 대상 채널의 고정 ID인 UCi9Sl8GnFdYoqEVXnojBPJw |
| video_id | 실제 기준물의 YouTube 영상 ID |
| selection_reason | 주제 유형·시청자 질문·러닝타임·자료 구성 중 제작본과 비교 가능한 지점 |
| origin_note | 원본 URL과 확인일, 영상·자막·썸네일 각각의 확보 경로, 자막 작성 방식, 편집·트림 여부 및 원본과의 시간 차이 |

분석에 쓰는 사본과 공개 가능한 출고 자산의 이용 조건은 각각 기록한다. 기준 영상에서 발견한 외부 자료는 원게시자·원자료와 이용 조건을 확인한 후 제작 자산 원장에 등록한다.

## 두 영상에서 확인할 일

제작본에서 대응하는 장면을 찾은 뒤 양쪽의 재생 시각을 각각 `HH:MM:SS`로 남긴다. 짧은 현상은 `finding`에 밀리초나 프레임 번호를 추가한다. 패키징은 각 썸네일과 제목을 먼저 보고 그 약속이 이행되는 영상 시각을 기입한다.

| 키 | 사람이 확인하는 방법 | 수정 책임 |
|---|---|---|
| hook | 첫 화면에서 생긴 질문, 구체적 이해관계, 시청자가 답을 기대하게 되는 첫 대사까지 본다. | 기획·대본 |
| structure | 핵심 주장→증거→해석의 연결을 양쪽에서 추적한다. 편집으로 빈 논리나 순서 역전이 생겼는지 본다. | 기획·대본·편집 |
| accuracy | 주요 수치의 분모·단위·시점과 발언 인용 범위를 각 원자료에서 확인한다. 서로 다른 주제에서는 같은 역할의 검증 장면을 대조한다. | 대본·팩트체크·자료 |
| visuals | 같은 역할의 장면에서 도해 크기, 시선 순서, 시야를 막는 요소와 한 화면의 정보량을 확인한다. | 자료·편집 |
| captions | 원본 화면 크기와 함께 글자 높이 비율, 최대 줄 수, 단위별 체류 시간, 음성과 자막의 시작 차이, 가림 여부를 확인한다. | 편집·자막 |
| audio | 말이 밀리는 구간과 음악이 발음을 가리는 구간을 같은 재생 환경에서 듣는다. 측정 시 기준물과 제작본 모두 동일한 범위·도구·단위로 기록한다. | 음향·편집 |
| packaging | 작은 화면에서 주 피사체와 문구가 읽히는지 보고, 제목이 건 약속을 실제 본문에서 어느 장면이 입증하는지 연결한다. | 썸네일·마케팅 |

**허용오차 설정 예시.** 회차 기획자가 빠른 설명 구간을 골라 자막 등장 시점과 해당 발화 시작 사이의 차이를 0.20초 이내로 맞추기로 정할 수 있다. 이 수치는 작업용 가정이다. 실제 기준 영상에서 발화·자막을 10회 측정했다면 표본 구간, 실제 분포, 해당 회차 목표와 예외를 따로 남긴다. 독립 검수자는 측정 1건 이상을 같은 방법으로 반복한다. 수치가 일치해도 자막이 수치 그래프를 가린다면 수정을 요청한다.

## 비교표와 반송

`comparison/scorecard.json`의 최상위에는 위 표의 일곱 항목과 reviewed_inputs를 둔다. reviewed_inputs에는 현재 brief 명령이 표시하는 edit, marketing, evidence 제출 번호를 그대로 기록한다. 각 값에는 `reference_at`, `candidate_at`, `finding`, `verdict`가 있어야 한다. 제출 가능한 판정은 `pass`다. 검토 중인 문제는 `handoff.json`의 작업 기록 또는 별도 결함 메모에 보관한다.

다음은 **형식 설명용 가상 예시 한 항목**이다. 시각과 측정값은 실제 채널 관찰이 아니다. 제출 시에는 나머지 여섯 항목에도 실측 근거가 필요하다.

```json
{
  "captions": {
    "reference_at": "00:00:18",
    "candidate_at": "00:00:23",
    "finding": "단위가 붙은 수치를 읽는 대응 장면을 비교했다. 제작본의 발화 후 0.12초에 자막이 시작되며 단위가 같은 줄에 보인다. 기준 장면도 수치와 단위가 한 줄로 유지된다.",
    "verdict": "pass"
  }
}
```

반송 예시 — 제작본 00:00:23에서 자막이 그래프의 단위를 가렸다. 편집팀이 자막 위치를 바꾼 뒤 변경된 마스터를 다시 제출한다. 대조팀은 같은 장면과 다음 컷의 자막 위치를 재검사하고 그 버전으로 비교표를 갱신한다. 내용이나 제목까지 바뀌면 해당 팀도 수정본을 인계한다. 독립 검수자는 원자료·재생·권리 원장과 비교 근거를 직접 확인한 뒤 승인한다. 출고팀은 그 승인에 사용된 버전을 납품 목록에 기록한다.

## 프로그램이 적용하는 기준

두 파일을 같은 FFmpeg 설정으로 분석한다. 기본 운영 허용차는 통합 음량 ±2 LUFS, 재생시간 ±15%(최소 1초), 후보 컷 간격 중앙값 ±25%(최소 0.35초), 자막 노출시간 중앙값 ±20%(최소 0.25초)다. 14개 양방향 허용차에 영상·썸네일 가로 및 세로 해상도 하한 4개를 더해 총 18개 항목을 측정한다. 제작본의 픽셀 수는 기준물의 해당 축 이상이어야 한다. 정책값은 tools/parity_metrics.py의 LIMITS와 MINIMUMS에 있다. 이 수치는 Jisikcat의 초기 제작 정책이다. 판단을 보류한 항목, 시각 범위 오류, 선행 제출 번호 변경, 계측 허용차 초과는 모두 출고 경로를 막는다. 측정 표본이나 제작 정책을 조정할 때는 비교 근거와 변경 이력을 남긴다.

프로그램은 파일을 해시로 묶는다. 실제 채널 소유 여부, 음악과 대사의 조화, 설명의 설득력은 사람이 확인한다. 제출자 식별은 운영자가 지정하는 이름에 의존한다.
