# Jisikcat 하네스 회고 · 2026-11-21

## 어느 회차에서 무엇이 실패했나

기준 커밋 `75852f4`를 별도 폴더에 풀고 3초 합성 영상과 자막·썸네일로 회차를 만들었다. 대조표의 7개 항목에 같은 1초 시각과 '확인'을 적었다. 독립 검수 문서에는 '보류: 자막이 핵심 수치를 가립니다. 수정 요청.'이라고 기록했다. 서로 다른 제출자 이름으로 실행했을 때 **독립 검수 #11, 출고 #12가 모두 접수됐다.** 당시에는 재생 가능한 파일, 대조팀의 pass, 독립 검수 문서의 존재를 검사했다. 마지막 검수자의 승인·보류 의사를 기계가 읽을 필드가 없었다.

## 수정과 재검증

|재현한 위험|바뀐 인수 기준|검증 방법|
|---|---|---|
|최종 검수에서 발견한 결함이 출고까지 전달되지 않음|독립 검수자가 대조 제출 번호, 일곱 항목의 양쪽 관찰과 등급, 전체 결정, 열린 차단 결함을 기록한다. 명시적 보류 표식이 남으면 승인을 거부한다.|미승인·자막 미달·열린 결함·이전 번호·결말 구간 밖 시각·보류 메모를 각각 제출해 거부를 확인한다. 수정 후 승인 경로도 실행한다.|
|전편 평균이 비슷해도 특정 구간에 결함이 남음|영상 길이를 벗어난 자막을 검사하고, 검정 화면·정지 화면·무음의 최장 및 누적 시간을 원본과 비교한다.|12초 영상에서 자막을 13~14초로 밀거나 오디오 꼬리 5초를 제거한다. 원본에도 존재하는 긴 정지 장면과 짧은 휴지는 허용하는지 함께 확인한다.|
|구두 반송 후 같은 산출물이 다시 인계됨|반송을 현재 제출 번호에 기록하고 의존하는 승인들을 무효화한다. 실제 산출물 내용이 바뀐 뒤 재접수하고 다음 팀이 다시 심사한다.|동일 반송 재시도, 이전 버전 반송, 인계 문구만 변경, 하위 팀 재검수, 기존 회차 업그레이드를 시험한다.|

**유지한 것.** 13개 팀의 병렬 제작 경로, 기존 역할별 스킬, 독립 심사자, 파일 해시와 제출 이력을 유지했다. 기획 담당은 크리에이티브 디렉터로서 약속한 질문과 결말을 책임지고, 출고 담당은 제작 진행자로서 차단 결함과 버전을 추적한다. 장면·주장·자산의 연결 예와 팀별 수정 경로는 [인수 기준](TEAM-CONTRACTS.md)에 있다.

## 아직 입증하지 않은 것

실험은 합성 미디어와 통제된 결함을 사용했다. 실명 인증, 기준 파일과 실제 유튜브 영상의 동일성, 검수자가 진실하게 전편을 재생했는지, 회차의 사실 정확도와 독창성은 자동 검사로 증명할 수 없다. 시청자가 느낀 동급 품질이나 실제 채널의 클릭률·유지율도 미측정이다. 입력하지 않은 결함이나 정해진 표식 밖의 자연어는 사람이 판독해야 한다.

## 다음 실제 회차가 끝나면

- **기준물 확보팀과 기획팀**은 같은 형식의 기준작과 선정 이유를 먼저 확정한다. 검수자가 실제로 대조할 수 있는 영상·자막·표지를 회차에 묶는다.
- **대조팀과 독립 검수팀**은 각자 화면과 음성을 확인한다. 서로 다른 평가가 난 장면은 두 영상의 시각, 시청자가 놓칠 정보와 수정 담당을 남긴다. 평가를 평균내어 미달 항목을 지우지 않는다.
- **제작 진행 담당**은 history의 실제 반송 건수, 수정 후 접수까지 걸린 시간, 같은 사유의 재발을 기록한다. 최초 제출 오류와 의존 팀의 재검토를 같은 결함으로 중복 집계하지 않는다.
- **성과팀**은 게시 후 같은 경과 시간·유입 경로·길이에서 관측 가능한 CTR과 구간 유지율을 대조하고 다음 회차에서 바꿀 변수 하나를 정한다. 표본이 작으면 결론을 보류한다.

검증 재실행은 저장소 루트에서 `python3 -m unittest discover -s tests -v`로 수행한다. FFmpeg와 FFprobe가 있어야 미디어 통합 테스트가 실제로 실행된다.
