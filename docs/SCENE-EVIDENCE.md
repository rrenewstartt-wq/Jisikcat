# 포맷 분석과 화면 근거 검수

15개 팀이 한 회차를 인계한다. 레퍼런스 분석 → 기준물 확보 → **포맷 분석** → 기획까지 기준을 먼저 정한다. 대본·팩트체크와 썸네일이 기획을 받아 작업한다. 대본에서 자료·권리와 내레이션으로, 두 팀에서 편집·자막으로 인계한다. 대본과 썸네일은 마케팅에도 전달된다. **화면 근거 검수**와 패키징을 마치면 대조 심사 → 독립 검수 → 출고 → 성과 회고로 이어진다.

|책임 팀|인수 기준|문제가 발견됐을 때|
|---|---|---|
|포맷 분석 `format`|선정 영상 ID, 원본의 도입·중반·결말 시각, 각 구간의 서사 기능·컷·자막·음향, 표지 구도·문구 위계·제목의 약속|파일이나 영상 버전이 다르면 기준물 확보팀으로 돌린다. 제작팀은 승인된 `format/profile.json`을 열어 구간별 연출을 참조한다.|
|대본·자료·편집|주장 ID를 발화 행과 팩트시트에 부여한다. 자료팀은 원자료와 이용 조건을 `sources.json`에 등록한다. 편집팀은 주장 발화 중에 해당 증거가 실제로 보이게 한다.|근거를 구할 수 없으면 대본의 주장 범위를 좁힌 후 관련 팀에 재인계한다.|
|화면 근거 검수 `visualproof`|모든 주장에 대해 현재 버전의 실제 자막 시각, 요구한 증거 유형, 등록 자산, 무음 재생 관찰과 기준 장면을 기록한다. 동일 자산을 다음 주장에 쓰면 새로 입증한 내용이 필요하다.|제작진이 자신이 만든 컷을 승인할 수 없다. 미해결행은 `hold`로 남겨 수정한다. 이미 접수된 산출물은 `reject`로 담당자에게 반송한다.|

`python3 tools/studio.py upgrade EP`는 누락된 양식을 추가한다. `brief EP 단계`와 `dispatch.py EP 단계`는 새 팀도 지원한다. 이전 기획 이후의 승인은 새 선행 제출에 맞춰 다시 받는다. 원본 미확보 회차에서 빈 기준표를 승인할 수 없다.

## 파일 작성 예

대본의 `C01 · 오후 1시에 가격이 바닥을 찍었습니다.` 행과 팩트시트의 `C01`에 대응해 `script/claims.json`에 `{"C01": "measurement"}`를 적는다. 허용 유형은 실문서 `document`, 관측·계측 `measurement`, 동작 `demonstration`, 가정 계산 `model`이다. 타입은 주장이 약속한 근거를 기준으로 정한다.

`visualproof/proof.json`의 `reviewed_inputs`에는 현재 `brief`의 제출 번호를 그대로 넣는다. 다음은 `claims` 객체의 한 행이다.

```json
{"C01": {"at": "00:00:27.100", "spoken": "오후 1시에", "asset": "시간별 가격과 그래프", "kind": "measurement", "anchor": "middle", "visible": "13시 표식에서 가격선이 −135.45 €/MWh에 닿는다.", "verdict": "pass"}}
```

`spoken`은 그 시각에 노출된 자막과 해당 ID의 대본 행에 실제로 있는 문구다. `asset`은 자료팀 등록명, `anchor`는 기준표의 `opening`, `middle`, `ending` 중 대응하는 기능이다. 정해진 파일, 버전, 시각, 유형, 주장 누락은 자동 검사한다. 화면이 실제로 주장을 입증하는지와 두 작품의 연출 완성도는 독립 담당자가 재생해 판정한다.

`python3 tools/studio.py inspect-proof EP`는 작업 중인 화면 근거표를 점검해 결함을 주장별로 표시한다. 원장에 승인 이력을 쓰지 않으므로 기준물 수급 중인 기존 회차도 사용할 수 있다. `python3 tools/studio.py frame-pair EP C01 --out /tmp/C01.png`는 두 영상의 기록된 시각을 읽어 좌측에 기준작, 우측에 제작본을 놓은 PNG를 만든다. 실제 크롭·자막 위치와 피사체를 비교할 때 사용하고, 소리·컷 전환은 원본 영상에서 해당 구간을 재생해 확인한다.
