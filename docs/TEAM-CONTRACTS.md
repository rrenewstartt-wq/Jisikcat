# 회차별 제작 책임과 팀 간 인수

기획 담당자가 **크리에이티브 디렉터**, 출고 담당자가 **제작 진행 책임자**를 겸한다. 전자는 시청자가 영상 끝에서 답할 질문, 소재에 어울리는 형식, 과장 없이 흥미를 만드는 표현을 결정한다. 후자는 담당자·선행 제출·작업 순서·병목·납품 버전을 추적한다. 대조 심사와 최종 검수는 서로 다른 사람이 맡는다. 역할 수는 13개다. [워크플로](WORKFLOW.md) · [품질 규격](QUALITY.md)

## 한 주장을 끝까지 추적하는 방법

회차 디렉터리와 CLI 제출 번호를 버전 기준으로 쓴다. 사람이 읽는 문서에서는 한 장면 안의 발화·증거·자산을 같은 식별자로 연결한다. 아래 표기의 이름은 작성 예시이며 CLI의 JSON 필드에 추가할 의무는 없다.

| 공통 표기 예 | 최초 작성 | 뒤에서 사용하는 방식 |
|---|---|---|
| 장면 S03, 기능 ‘예외를 보여 주기’ | 기획 `brief.md` | 대본과 음성 테이크는 S03을 유지한다. 편집본이 나오면 해당 구간의 실제 시작·끝을 기록한다. |
| 주장 C02, 자료 표 2의 2024년 열 | 대본 `facts.md` | 같은 수치의 분모·단위·기간을 자막, 도해, 썸네일에 짧게 옮길 때도 의미를 유지한다. |
| 자산 A04, S03에 쓰는 자체 도해 | 자료 `sources.json` | 편집·마케팅이 파일, 크레디트, 가공 범위와 데이터 출처를 같은 기록에서 찾는다. |
| 제작 약속 ‘누가 어떤 조건에서 혜택을 받는가’ | 기획 `brief.md` | 마케팅은 문구를 바꿔도 답의 범위를 지킨다. 대조팀이 실제 회수 시각을 적는다. |
| 결함 D01, C02의 분모 누락 | 처음 발견한 팀 | 위치·증상·영향·수정 담당·재검사 방법·해결 제출 버전을 남긴다. |

편집 전에는 장면 번호나 대본 문단으로 안내한다. 마스터가 나오면 재생 가능한 시각을 붙인다. 서로 다른 파일의 시각은 따로 쓴다. 자료 이용 조건이 바뀌면 자료팀이 영향 샷을 찾아 편집·썸네일·설명 담당자에게 알린다. 제목만 바뀌어도 패키징 대조를 다시 한다. 제출을 고친 뒤 `status`와 `brief`에 나타나는 선행 버전으로 재인계한다.

## 팀장이 결정하고 인계할 일

| 팀 | 끝까지 책임질 질문 | 인계 전에 동료가 해 볼 검사 | 불일치가 나면 |
|---|---|---|---|
| 분석 | 패턴이 어떤 표본에서 얼마나 자주 나오는가? | 같은 영상 ID와 시각으로 관찰 1건을 재현하고 반례를 찾는다. | 표본 섞임·동명이인·관찰과 가설 혼동을 분석팀이 정정 |
| 기준물 확보 | 동일 작품·버전의 영상/자막/표지가 모였는가? | 초반·중간·후반 대사의 위치, 표지와 영상 ID, 파일별 출처를 맞춘다. | 자막 시차는 버전부터 추적, 작품 선정 문제는 분석팀과 재선정 |
| 기획 | 약속을 납득시킬 가장 강한 장면이 있는가? | 첫 질문과 마지막 답을 이어 읽고 중간 증거 하나로 결론을 뒤집을 반례를 묻는다. | 증거 미확보 시 주제 범위를 줄이고 리서치를 다시 지정 |
| 대본 | 숫자와 주어를 빼거나 바꿨을 때 결론이 달라지는가? | 원자료로 수치를 재계산하고 조건부 결론과 음성 문장을 대조한다. | 근거가 약하면 주장의 강도를 낮추고 기획에도 영향 통보 |
| 자료 | 해당 컷이 바로 그 주장을 뒷받침하는가? | 원문에서 기간·지역을 찾고 파일별 사용·편집·배포 범위를 확인한다. | 증거 부적합 시 대본으로, 권리 미확인 시 대체 제작으로 |
| 썸네일 | 축소했을 때 시청자는 무엇을 볼 것으로 기대하는가? | 모바일 표시폭으로 줄여 피사체와 카피를 읽고 그 기대를 본문에 대응한다. | 카피 범위는 기획·대본과 조정, 오독을 부르는 도상은 재디자인 |
| 음향 | 말만 들어도 핵심 비교와 단위를 정확히 복원할 수 있는가? | 분모·단위 문장을 대본 없이 받아 적고 피크·배경 간섭을 다시 듣는다. | 발음·문장 쉼은 재녹음, 문장 자체 모호성은 대본에 반송 |
| 편집 | 화면과 소리가 같은 순간에 같은 주장을 전달하는가? | 그래프 축과 숫자가 보이는 동안 대응 발화를 들을 수 있는지 샷 단위로 본다. | 출처·테이크·그래픽 중 오류가 시작된 팀에서 수정 |
| 마케팅 | 제목·표지의 합이 본문 결론보다 커졌는가? | 제목을 읽은 동료가 예측한 답과 결론 장면을 비교한다. | 오해를 만드는 최종 문구는 줄이고 썸네일 약속도 재검토 |
| 대조 | 기준작의 기능과 제작본의 대응 기능을 실제로 보았는가? | 비교표에서 양쪽 시각을 열고 판정 문장과 계측 결과를 재현한다. | 불일치 차원과 해당 장면을 원 담당 팀에 반송 |
| 독립 검수 | 출고 직전에도 가장 위험한 반론이 남는가? | 직접 원출처를 따라 핵심 주장 재계산, 최종 마스터 전편 재생 | 내용 오류와 권리 미결은 반송, 고친 파일로 영향 항목 재검사 |
| 출고 | 정확히 어떤 파일·제목·공개 범위가 승인됐는가? | 승인 버전과 납품 파일 해시를 비교하고 게시 시각과 상태를 대조한다. | 버전 변경 시 재검수, 실제 게시 승인 대기 시 준비 상태 기록 |
| 성과 분석 | 어떤 관찰이 다음 편의 어떤 결정에 영향을 주는가? | 같은 경과 시간과 유입 경로에서 분모·표본을 확인한다. | 소유자 데이터가 없으면 미측정 사유와 수집 시점만 남긴다. |

## 편집회의 실습 — ‘평균이 올랐다’는 썸네일

아래의 조직, 수치, 이견과 수정 과정은 **합성 자료로 하는 편집 훈련**이다. 산술은 재현할 수 있다. 실제 회차의 조회 성과·시청자 반응·대조 심사 통과를 뜻하지 않는다.

**초안.** 가상의 다섯 사람 월급이 첫해에는 각각 200·200·200·200·200만원, 다음 해에는 200·200·200·200·300만원이다. 대본 C02는 “월급이 10% 올라 모두가 더 벌게 됐습니다”라고 썼다. 표지는 ‘전원 10% 인상’, 도해는 ‘평균 200 → 220’ 막대 두 개다.

**반대 심사.** 기획자는 ‘인상률이 눈에 들어온다’며 초안을 지지했다. 팩트체커는 다섯 사람의 전후 차이를 계산해 네 명이 0, 한 명이 100만원 증가했음을 제시했다. 썸네일 담당자는 표지만 본 사람이 ‘나도 10% 받았다’고 이해할 수 있다고 지적했다. 대조팀이 제기한 쟁점은 그래프 수치 자체가 맞아도 화자의 결론은 틀릴 수 있다는 점이다.

| 담당 | 변경 전 | 수정한 문장·화면 |
|---|---|---|
| 기획 | 돈을 더 번 사람들의 이야기 | ‘평균 월급이 오르면 몇 명의 월급이 오른 걸까?’로 회차 질문을 고침 |
| 대본 | 전원 소득 인상 | “다섯 명의 평균은 200만원에서 220만원이 됐습니다. 인상된 사람은 한 명입니다.” C02에 합계·인원·중앙값을 병기 |
| 자료·편집 | 두 개의 평균 막대 | 같은 다섯 사람을 두 줄에 대응시킨 뒤 변한 한 사람만 강조. 화면에 ‘가상 예시, 단위 만원’ 표시 |
| 썸네일·마케팅 | 전원 10% 인상 | ‘평균은 10% 올랐는데?’와 다섯 개의 급여 봉투를 배치. 실제 인상 대상의 수를 시청자가 추측하도록 설계 |
| 음향 | ‘모두’를 강조 | 두 평균을 읽고 잠시 쉰 뒤 ‘한 명’을 읽는다. 숫자와 단위를 한 호흡으로 녹음 |

**재검사.** 첫해 합계 1,000÷5=200, 다음 해 1,100÷5=220이다. 인상률은 (220−200)÷200=10%, 양년 중앙값은 200, 개인별 인상 비중은 1÷5=20%다. 이 계산으로 수정 대본이 입증되는지 검토할 수 있다. 실제 제작에서는 독립 검수자가 렌더 화면과 녹음, 표지, 설명란에서 ‘모두’가 남은 구간을 다시 찾고 최종 입력 버전을 적는다. 실습의 끝 상태는 **수정안 작성**이다. 실제 영상·음원·원본 대조·게시 지표는 별도로 확보해야 한다.
